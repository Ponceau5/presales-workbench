# Agent 执行层与模块规划

## 产品定位

多岗位售前协作工作台。项目是资料与成果的归属边界；岗位工作区使用同一套交互，Skill与工具负责完成业务任务。界面保持紧凑，技术配置和运行记录不作为普通销售页面的说明内容。

## 当前 LangGraph 接入范围

已安装 LangGraph 1.2.15、SQLite checkpoint 3.1.2，运行在现有 FastAPI 进程内。没有安装 LangGraph Server、LangSmith服务、Redis、Celery或Deep Agents。

F7 `/ask-stream` 的回复执行进入状态图：

1. 验证执行阶段。
2. 使用现有生成逻辑与 SSE 协议生成并保存回复。
3. 保存检查点，成本资料审核后等待参数确认；需要核对的正式草稿等待成果采纳。
4. 参数确认结束审查运行，后续生成作为关联请求启动；采纳成果结束其核对等待。

当前资料选择、参数校验和确定性成本计算仍复用路由中的准备逻辑，尚未拆成独立图节点。F5/F8仍使用原执行路径。本次不是整个系统的全面迁移。

点击“成本估算表”仍先核对缺项；“资料与参数”仍只在用户点击时打开。失败回复只增加一个“重试”按钮。恢复请求使用原始参数，资料或Skill版本发生变化时拒绝复用原运行，需重新发起。

## 状态、恢复和权限

- `workbench.sqlite3/runtime_runs`：运行ID、项目、工作区、操作者、对话回复ID、阶段、输入指纹、状态和错误。
- `server/.local/agent-runtime/checkpoints.sqlite3`：LangGraph持久化检查点，包含本次执行快照，不使用内存Saver。
- 输入包含项目资料版本、Skill规则、参数及请求。单次快照上限512KB；当前进程默认最多同时生成2个任务，可用 `PRESALES_AGENT_CONCURRENCY` 设置。
- 每个运行使用文件锁，防止重试和确认并发修改同一检查点。
- 同一个项目、岗位、账号和回复ID不会重复生成已完成回复。生成后落库但检查点未写完的故障，可从已落库回复恢复，不重复调用模型。
- 恢复、确认及查询必须通过当前项目权限验证，并匹配原操作者。正式操作还校验当前岗位负责人；模型完成后保存前再次校验权限。
- 重试支持进程重启后继续未完成节点；不保证从模型输出中间某个token继续。模型调用失败时可能重新调用该节点，供应商仍可能收取前一次费用。
- 流式连接断开不保证供应商立刻停止生成，也不保证后台调用立刻终止。已保存成果可再次读取。
- 两个SQLite库必须一起备份，检查点数据库不放OSS挂载盘。数据库可使用SQLite备份API生成一致快照后上传OSS。
- 文件锁和并发限制适用于当前单机部署。扩展至多台服务器前，需更换数据库检查点实现、分布式执行锁及任务队列。

接口：`GET /api/projects/{项目}/workspaces/F7/runs/{运行ID}/state`；`POST .../runs/{运行ID}/retry`。接口只返回该操作者的执行记录。技术信息不新增到普通用户页面。

| 审计与运行监测 | 已有业务审计；此次新增运行状态和失败记录 | 汇总错误率、耗时与恢复次数；完整链路追踪按需接入OpenTelemetry，不保存API密钥 |
| 发布、备份与恢复 | 源码在GitHub；账号/业务数据独立于代码 | 数据迁移版本、定期备份、恢复演练；避免用代码部署覆盖真实业务数据库 |

先补齐工具授权、输出校验、业务样本评测和使用量统计，比同时引入多个Agent框架更有价值。当前2核2GB阶段不增加重型平台；开源模块应替换明确的缺口，而不是重复已有业务能力。

## 选型边界

LangGraph用于明确步骤和人工确认；轻量工具调用Agent用于资料判断。Deep Agents可在真正需要长程自主规划时评估。OpenClaw可作为受限执行服务接入，但不能替代项目级权限、不可变输入版本和成果核对规则。
