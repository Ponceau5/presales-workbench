# Casdoor 功能与工作台分工

后台入口：http://127.0.0.1:9090（仅本机；未登录时先显示登录页）。
工作台入口：http://127.0.0.1:7101。
本地启动：在项目目录运行 `sh scripts/start-casdoor.sh`。两者共用身份认证，但后台操作仍需管理员权限。

| 能力 | 对售前工作台的用途 | 当前情况 |
|---|---|---|
| 账号和密码管理 | 建账号、停用、修改密码、账号恢复 | 已承担认证；工作台内创建和重置入口尚未全部整合 |
| 单点登录 | 以后与公司已有系统共用员工身份 | 当前工作台使用 OIDC；企业身份源另行配置 |
| 组织与用户组 | 按团队管理用户，后续接公司组织目录 | 可配置；不自动决定项目权限 |
| 多因素认证 | 对管理员等重要账号增加验证 | 可配置，尚未启用 |
| 会话与登录记录 | 查看登录情况、处理账号异常 | 可用于身份侧管理；业务变更另记 |
| 角色与权限策略 | 通用角色及资源授权 | 工作台项目可见、唯一负责人等规则仍由业务后端执行 |

## 当前最值得使用的功能

优先把账号创建、停用及密码恢复统一到工作台入口，后台调用 Casdoor；以后有企业登录需求时接入公司身份源。管理员可按需要开启多因素认证。

项目文件、具体资料版本、配置清单、成本表、Skill、岗位交接和项目负责人规则保留在工作台。Casdoor 不代替项目存储或业务流程。

Casdoor 后台还有 MCP、代理、商城、支付等功能。当前没有启用这些能力的业务需求；不必因为菜单里存在就接入。
