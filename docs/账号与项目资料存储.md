# 账号与项目资料存储

## 项目定位

这是多岗位协作的售前工作台：每个项目有一份共享资料池，岗位读取输入、执行 Skill、核对并交付成果。相同工作区使用一套代码和交互，项目决定资料、参数和输出。

## 管理账号和授权

管理员在工作台的“权限管理 → 账号管理 → 管理账号”打开 Casdoor。创建账号后返回工作台点击“同步账号”，选择岗位并添加到工作台，再在项目授权中设置可见项目或岗位负责人。

新账号不会自动获得任何项目，也不会因为 Casdoor 中的管理员标记自动成为工作台管理员。相同项目与岗位只有一个负责人；其他获准人员可查看和试运行个人草稿，不能覆盖正式流程。

Casdoor 停用/删除账号后，工作台在最长约 30 秒的状态缓存结束后拒绝其后续请求；已有正在执行的请求不被此机制立即中止。账号服务不可用时拒绝需要重新验证的请求。退出工作台会撤销工作台会话；Casdoor 自身的登录会话由 Casdoor 管理。

## 文件到底放在哪里

正式环境沿用已配置的私有 OSS Bucket：`salesworkbench`，地域华北6（乌兰察布）。ECS 内网 Endpoint 为 `oss-cn-wulanchabu-internal.aliyuncs.com`；浏览器上传下载使用公网 Endpoint。

| 内容 | 保存位置 | 业务关系 |
|---|---|---|
| 项目原始资料与上传模板 | OSS `projects/<项目ID>/originals/<文件ID>.<格式>` | 按项目保存一份；文件ID与版本对应，不覆盖旧原件 |
| 已导出的成果文件 | OSS `projects/<项目ID>/outputs/<成果ID>.<格式>` | 成果ID对应不可变版本 |
| 项目资料标题、版本、文件地址与解析正文 | 工作台数据库 `documents`、`document_pages` | F5/F7/F8共享同一项目目录 |
| 岗位输入、模板分类 | `workspace_material_tags`，成本输入引用等业务表 | 引用项目文件；无需复制原件 |
| 核对后成果与历史版本 | `workspace_artifacts`；既有F5专用成果表 | 其他岗位可读取上游成果；默认显示最新，可选择历史版本 |
| Skill样本 | `role_file_samples`、`flow_samples`中的索引；原件经统一存储层进入OSS | 保留项目和工作区归属 |
| 对话、Skill、执行状态、权限 | 工作台数据库 | 不放GitHub，不使用浏览器缓存作为唯一副本 |
| 源代码 | GitHub | 不包括资料库、账号数据库、模型密钥 |

本地开发未启用 OSS 时，原件在 `server/.local/files/`，业务索引仍在工作台数据库。仓库 `.local` 是实际开发数据，不能当临时文件清理。本次没有迁移或修改云端。

共享池是项目级目录和数据库索引，不是每个岗位电脑上的独立文件夹。岗位“资料”弹窗呈现该项目的输入、岗位模板和成果；上游成果通过关联读取。

## 流量与增长

新上传的项目资料支持浏览器直传 OSS；资料预览使用已解析正文；下载通过短期签名地址直达 OSS。样本上传与解析仍经后端，因此尚未做到所有上传都直传。调用模型只取本次需要的项目资料。

OSS 公网下载仍会产生 OSS 流量费；直传/直下载减少 ECS 中转流量，不代表免费。生成文件按版本保存，下载不重复写入相同对象。

两份 SQLite 数据库分别服务账号和业务，保存在运行服务器的本地磁盘；备份上传 OSS，不能把活动数据库放 OSS 挂载盘。高并发写入或多实例部署时迁移 PostgreSQL。Casdoor支持更换数据库，工作台需适配现有SQLite SQL；不是仅改配置即可迁移。

## 执行框架

当前工作台尚未引入 LangGraph 或 OpenClaw。OpenClaw可以作为经受限工具接口接入的执行服务，但项目权限、固定版本输入和人工确认仍需工作台实施。不能给多个项目共用的 Agent 不受约束的文件访问，再指望提示词隔离资料。

现阶段完成账号与存储链路，并保留现有流程；需要断点恢复与多步人工确认时再引入运行时，不在2GB服务器上叠加完整Dify/ERP平台。
